# 划词诊断

适用于已经确认运行新版、自动划词和兼容取词均开启，剪贴板 / Ctrl+Alt+T 可用，但自动划词从不显示的情况。仅凭云端普通文本框测试不能判断具体机器的故障，本工具收集分段状态来缩小范围，不宣称已知现场根因。

## 操作

1. 右键托盘图标，打开“划词诊断”。点击“显示测试”，确认按钮旁是否出现叶片。这个测试不读取选区、不调用翻译接口；点击测试叶片也不会发送内容。
2. 回到原来出问题的网页或 Word，实际划选一段文字两三次。
3. 再打开诊断窗口，点击“刷新 → 复制报告”，将报告作为文字提供给维护者，并说明显示测试是否能看到叶片。
4. 可主动点击“恢复划词”：它保存自动划词开启状态、结束本次暂停 / 手动编辑保护，并请求安全重新安装监听；然后在其他程序重新划词。API / 语言草稿不随此操作提交，原文草稿先保留。此操作不自动打开兼容复制或改变翻译模式。

报告只在内存保存固定标签、计数和数值错误码，最多保留 32 个最近决策；不自动写盘、不联网、不包含选中文字、窗口标题、剪贴板内容、服务地址、模型名或密钥。复制报告会按用户操作替换当前剪贴板为这份诊断文字。

## 判读

- HookDown / HookUp 没有变化：检查监听安装、输入设备和 HookHealth 错误。
- NotifyPosted 增加而 AppDownAccepted / AppUpAccepted 不增加：看暂停、手动保护、来源窗口变化或通知丢弃等固定原因。
- 已排队但取词没有结束：看 Warm / Capture 的 Started 和后续结果，不能把 UIA 软超时当作可中断的硬超时。
- AutoCapture 失败而 HotkeyCapture 以 ManualCopy 成功：自动只读读取 / 兼容复制的适用条件与快捷键复制兜底不同，需要依据具体错误码分析。
- 已取得文字但图标显示失败：看 Render 的数值系统错误和显示测试结果。

状态以报告当时为准。Hook 请求重启成功入队不代表已经完成；松开鼠标后稍等并刷新，看实际安装结果。

## 验证边界

普通 Win32 EDIT 选区路径绕过 UIA。Wine 10 的相关 UIA 调用存在 E_NOTIMPL，实现中的非空 / 几何假对象测试也不能证明真实浏览器或 Word 可用。0.10.2 增加原生 Windows 的实际控件 UIA 测试，Wine 明确跳过该单项；它验证系统控件链路，也不等同实测每个浏览器、Word 和 PDF 版本。

本机问题是否解决，以实际划词和报告为准。此前 0.10.1 的最小化 / 延迟选区修复仍保留，说明见 [恢复记录](selection-recovery-0.10.1.md)。
