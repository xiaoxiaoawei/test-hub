# 0.10.1 划词恢复

本次针对“所有软件划词都没有图标”排查全局监听与模式状态。没有从用户机器读取日志，不能断言用户现场只由一个原因造成；以下分别记录可复现问题与代码中的恢复缺口。

## 手动框最小化

0.10.0 打开手动翻译时设为暂停自动划词，保护输入草稿。显式关闭会恢复，但最小化只调整布局，未离开手动模式，因此任何其他软件都不再触发取词。

正式 0.10.0 的真实输入已复现：普通选词显示叶片，Ctrl+Alt+Space 打开手动框，通过系统最小化操作后再实际划词无叶片；还原并关闭手动框后立即恢复。不是浏览器 API 或翻译服务的问题，过程中没有模型请求。

修复在收到真实最小化事件时先保留手动草稿、离开手动模式，再恢复原先允许的自动监听。显式关闭自动划词、本次暂停等用户选择保持有效。再次使用手动快捷键仍可继续原文草稿。

## 全局钩子

旧版 WH_MOUSE_LL 安装在主界面线程，只有启动时安装一次。[Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)说明：低级鼠标回调运行在安装线程上下文；Windows 7 及以后，超过 LowLevelHooksTimeout 可被静默移除，无法查询是否已移除；Windows 10 1709 及以后超时上限为 1000 ms。

本版将安装和消息循环放入独立监听线程，只发送手势候选，取词、剪贴板、HTTP 与绘制均不在回调执行。暂停状态通过原子值与变更序号跨线程同步，旧按下事件不能跨暂停成为新手势。健康检查只在实际指针位置与最近回调持续不一致，且物理左右键均松开时重新挂钩；静止时不反复安装，丢失的手势不回放，也不补读旧选区。线程关闭时不无限阻塞界面。光标静止、仅在同一点快速点击而没有位置差异时，不据此判断钩子丢失；后续有可观察的移动后才可能恢复。

该代码风险有官方语义依据，不等于已在用户机器抓到钩子超时。兼容层与原生 Windows 的实际检查须在构建记录中分别注明。

## 延迟提交的选区

原生控件首次读取为空会立即结束本轮。对于鼠标松开后才提交选区的控件，即使稍后选区有效，也错过显示机会。

真实拖动、多次点击或 Shift 选择首次为空时，保留原有有界重试机会。没有文本时继续保持隐藏，确认有效文字后才显示；新手势或切换前台会取消旧轮次。普通点击、密码保护、内容验证以及兼容复制的独立设置保留，不通过预弹图标来掩盖读取失败。
