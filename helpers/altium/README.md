# Altium native library adapter

Independent C# adapter using the published `OriginalCircuit.AltiumSharp` 1.0.2 NuGet package and OpenMcdf 2.4.1. It contains no binaries or code from the inspected application. Requires the .NET 10 runtime; development requires the .NET 10 SDK. This helper is intended for Windows x64.

From the repository root:

```powershell
dotnet publish helpers/altium/PackageStudio.Altium.csproj -c Release -r win-x64 --self-contained false -o helpers/altium/publish
Get-Content request.json -Raw | & helpers/altium/publish/PackageStudio.Altium.exe
```

stdin accepts one JSON object with `parts`, `outputDirectory`, `libraryName`, `includeSymbol` and `includeFootprint`. Parts follow `internal/core/types.go`: millimetres, Y downward, pin rotation from electrical endpoint toward the body. stdout contains exactly one JSON result `{directory,files,warnings}`; errors use stderr JSON and exit code 1. Library files are written in the requested directory. Existing library files are never overwritten.

Implemented: SMD/through-hole/NPTH pads, round/oval/rectangular/rounded rectangular shapes, round/slot holes, PCB tracks, circles, filled polygons, polygon outlines and text; schematic pins, rectangles, lines, polygons, multi-unit symbols, hidden metadata, footprint model names. Identical footprints shared by several values are deduplicated. Input Y and angles are converted to Altium coordinates.

Limits: custom polygon pads stop the export; 3D STEP embedding is not implemented. Rounded pad corners use 25% because the core schema does not specify a radius. Schematic circles use 64-segment closed polylines and graphical strokes use Altium's Small preset. Courtyard/fabrication drawings use Mechanical 1/2/3/4/5 and require role configuration in AD. Symbols associate footprints by model name, not an absolute library path. Unknown PCB layers and non-cardinal schematic pins fail explicitly. This is an initial adapter, not complete parity with every Altium format feature.

All twelve KiCad pin electrical types are accepted. `input`, `output`, `bidirectional`, `tri_state`, `passive`, `open_collector` and `open_emitter` map to their Altium equivalents. `power_in` and `power_out` both map to Altium Power. The stable AltiumSharp enum has no Unknown/Undefined/NoConnect value, so `unspecified`, `free` and `no_connect` map to Passive with an explicit ERC warning. Every pin retains its original type in its description. These mappings preserve geometry and pin numbers while identifying the source ERC distinctions that Altium cannot express through this API.

Each export is read back using the same library to check the container and component count before publishing the files. Dependency diagnostics are returned in `warnings`; notably its text-record reader can report an unexpected record size for a text record written by the same package. Such output needs review in AD. This does not replace placement and ERC/DRC checks in the target AD version. The standalone smoke check additionally verifies pad count, positions and sizes and both pin directions:

```powershell
& helpers/altium/publish/PackageStudio.Altium.exe --self-test C:/path/to/a/new/test-directory
```

Known dependency limitation (not fixed): NuGet flags OpenMcdf 2.4.1 for [GHSA-jxpf-xq2m-q525](https://github.com/advisories/GHSA-jxpf-xq2m-q525) and [GHSA-5qwm-7pvp-w988](https://github.com/advisories/GHSA-5qwm-7pvp-w988). Both advisories describe denial of service while reading a malicious Compound File Binary container whose directory sibling links form cycles. The former affects directory enumeration; the latter includes name-based storage/stream lookup. An affected read can loop indefinitely, so `try/catch` alone is not protection.

The reviewed `Program.cs` accepts geometry JSON on stdin or generates its own smoke-test geometry. Its only native-library reads are the temporary files written by that same export and the files generated by the same smoke test. There is **no external .PcbLib/.SchLib/CFB import, native-library merge or append interface**. Thus the advisories' supplied-malicious-CFB input scenario is not exposed by the current geometry export API. This is a scope restriction, not a claim that the dependency itself is patched.

Upstream fixes are OpenMcdf 3.1.3 for GHSA-jxpf-xq2m-q525 and 3.1.4 for GHSA-5qwm-7pvp-w988; removing both requires at least 3.1.4. NuGet publishes no patched 2.4.x version. OpenMcdf 3.x has a rewritten API: `CompoundFile/CFStorage/CFStream` are replaced by `RootStorage/Storage/CfbStream`. A scratch build with 3.4.0 compiled but failed the real export with `TypeLoadException: OpenMcdf.CompoundFile`, confirming that changing only the package version breaks AltiumSharp 1.0.2. A future migration must port the CFB reader/writer boundary or adopt a maintained Altium library using the patched API, and rerun real generation/read-back checks before enabling any external native-library input. NuGet audit warnings remain enabled and unsuppressed.
